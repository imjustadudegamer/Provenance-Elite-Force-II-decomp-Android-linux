# Licensing

This repository is **not** covered by one licence, and it cannot be. It contains
three bodies of source that are governed by different terms, and two of those
terms are mutually exclusive when they meet in a single file. This document
states which terms reach which part, and where the project cannot satisfy a term
it states that too rather than papering over it.

The project is **unofficial**. It is not affiliated with, endorsed by or
sponsored by Ritual Entertainment, Activision, id Software, Raven Software,
Paramount or CBS. It is **non-commercial**. It ships **no game assets**: the
player supplies their own retail installation. It comes with **no warranty**.

## The four provenance buckets

Every native source file under `app/src/main/cpp/code/` carries a notice that
declares one bucket, and `PROVENANCE.tsv` records the bucket, the nearest
ancestor the decision was taken from and the similarity that supported it. The
ledger is generated by `tools/license_notices.py` and checked by
`tools/provenance_ledger.py`; the notices are enforced by `tools/license_lint.py`.

| Bucket | What it is | Notice | SPDX id |
|---|---|---|---|
| GPL lineage | id Tech 3 through OpenMoHAA, including the vendored tree under `code/thirdparty/` | the ancestor's own GNU GPL notice, kept verbatim | `GPL-2.0-or-later` |
| SDK-derived | Elite Force II game logic transcribed from the Ritual EF2 SDK | the SDK's per-file Ritual banner, kept verbatim | `LicenseRef-Ritual-EF2-SDK` |
| Retail reconstruction | engine, cgame, UI and model-layer code the publisher never released as source, rebuilt from the retail binaries | the port asserts no copyright and grants no rights | `LicenseRef-EF2-Retail-Reconstruction` |
| Vendored | a third party's component with its own notice (GameSpy, lcc, zlib, libjpeg, ...) | that party's notice, restored verbatim and never relabelled | (the vendor's own terms; see `THIRDPARTY.md`) |

`code/thirdparty/` keeps the notices it shipped with. Files that carry a
third party's own notice are never given a project SPDX id.

## 1. The engine lineage: GNU GPL v2 or later

The engine, `code/qcommon/`, `code/botlib/`, `code/renderercommon/`,
`code/renderergles3/`, `code/sdl/`, `code/sys/` and `code/thirdparty/`, descends
from id Software's Quake III Arena release, through ioquake3 and OpenMoHAA.
Those files are free software under the GNU General Public License, version 2 or
(at your option) any later version. The full text is `COPYING.txt` at the
repository root. Each file carries the ancestor's own notice, byte for byte, with
`SPDX-License-Identifier: GPL-2.0-or-later` added beside it; files the port has
changed also carry a change notice, as GPLv2 section 2(a) requires.

## 2. The Elite Force II game layer: the Ritual SDK agreement

`Star Trek: Voyager, Elite Force II` (2003) was developed by **Ritual
Entertainment** and published by **Activision**. Raven Software developed the
2000 predecessor, *Star Trek: Voyager, Elite Force*; it did not develop the
sequel. In 2003 Ritual released the Elite Force II SDK, server-side game code
for the 1.10 patch, under a Limited Use Software License Agreement. That
agreement is dated 2003-10-15 and is reproduced verbatim in this repository at
[`docs/EF2-SDK-licenseAgreement.txt`](docs/EF2-SDK-licenseAgreement.txt).

The `fgame` module, and the SDK's reusable headers, derive from that SDK. They
are **not** under the GNU GPL and must not be labelled as if they were:

- **§2(e)** forbids commercial exploitation, and **§3(a)** permits distribution
  only free of charge, for non-commercial purposes, by electronic means, for use
  with the full retail game;
- **§2(f)** forbids disassembling, reverse engineering, decompiling or modifying
  the Software, and **§2(j)** forbids preparing derivative works based on it;
- **§2(k)** forbids removing or altering the copyright and licence notices, which
  is why the SDK's per-file banner is restored intact on every SDK-derived file;
- **§8** forbids sublicensing and terminates the licence automatically on breach.

### The two terms this project cannot satisfy

**The SDK agreement's §2(f) and §2(j) cannot be satisfied by this project's own
method, and the project does not pretend otherwise.** §2(f) forbids reverse
engineering and modification of the SDK, and §2(j) forbids derivative works
based on it. The port's game layer is a modified, transcribed, rebuilt body of
code: it is exactly a derivative work, produced in part by reading the retail
binaries. Anyone distributing SDK-derived material from this tree therefore
depends on §3(a)'s New-Creation grant, not on a clean reading of §2(f)/(j), and
§3(a) is itself limited to free, electronic, non-commercial distribution for use
with the full game. If that is not a grant you can rely on, do not distribute the
SDK-derived part.

### The contradiction recorded, not resolved

The SDK ships two notices that do not agree. `licenseAgreement.txt` §3(a)
permits free electronic non-commercial redistribution with the Agreement
attached; the per-file banner says the source *"may not be distributed and/or
modified without expressly written permission by Ritual Entertainment, Inc."*
The package's own `readme.txt` names `licenseAgreement.txt` as the full
agreement, so this project treats the package agreement as the operative grant
and keeps the stricter per-file banner intact as §2(k) requires. It does not
claim that the two can be reconciled.

### The Agreement travels with the source

§3(a) makes the grant conditional on the Agreement accompanying each copy. A copy
is therefore part of this repository at
[`docs/EF2-SDK-licenseAgreement.txt`](docs/EF2-SDK-licenseAgreement.txt), byte
for byte from the SDK package, and any distribution of SDK-derived source from
this tree must include it.

### The indemnity

§6 provides that the licensee indemnifies Ritual and runs to whoever publishes
the SDK-derived material, and it sets Texas law and Dallas County venue. That is
the publishing party's exposure, not Ritual's.

## 3. Rebuilt from the retail binaries: no licence granted

The publisher released no source for the client-game module, the UI layer, the
model/container layer or the 2003 engine's own additions. Those files were
reconstructed from the retail binaries. This project **asserts no copyright in
them and grants no rights to them**: they remain the property of their respective
rights holders, and they are covered neither by the GNU GPL nor by the Ritual SDK
agreement. They carry the statement above and the identifier
`LicenseRef-EF2-Retail-Reconstruction`, which is a marker that no licence is
granted, not a licence.

A file never carries both a GNU GPL notice and a Ritual banner. GPLv2 section 6
forbids imposing further restrictions on recipients, and the SDK agreement
imposes them, so the two cannot govern the same file. Where the provenance of a
file could not be established, the honest treatment is the no-rights statement,
not a licence claim.

## 4. No single licence covers the tree

Because the GPL and the SDK agreement cannot both reach one file, and because
part of the tree is not the project's to license at all, no single identifier
describes the whole repository. A distributor must read `PROVENANCE.tsv` (or the
per-file notice) for each file. The repository root therefore carries no blanket
`LICENSE` file; the engine licence text is `COPYING.txt` and the SDK agreement is
`docs/EF2-SDK-licenseAgreement.txt`.

## Forks and redistribution

If you fork or redistribute this repository or a build made from it:

- keep every notice, banner and SPDX identifier intact;
- ship `docs/EF2-SDK-licenseAgreement.txt` with any SDK-derived material, as
  §3(a) requires;
- keep the engine and the SDK-derived modules as separate programs, joined only
  through the SDK's published interface, so the GPL does not reach the
  SDK-derived code and the SDK restrictions do not reach the GPL code;
- do not ship retail assets, and do not use the material commercially.

## Checks in this repository

- `tools/license_lint.py`, every source file carries its provenance notice, and
  no file carries two conflicting notices.
- `tools/ship_text_lint.py`, shipped markdown keeps one impersonal voice, and no
  shipped text names a user home path or a `.cfg` outside the engine's own set.
- `PROVENANCE.tsv`, the per-file ledger; `tools/provenance_ledger.py` regenerates
  and checks it against the ancestor corpora.
